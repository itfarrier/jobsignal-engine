    Create `scripts/nocodb_bootstrap.py` following the exact structure from RESEARCH.md lines 656-842. The script must be self-contained (only dependency beyond stdlib is `requests`).

    ### Module Structure

    **Shebang + Docstring:**
    - `#!/usr/bin/env python3`
    - Module-level triple-quoted docstring explaining purpose, usage examples for all 4 flags (--table, --force, --import-data, --skip-setup), and CLI invocation pattern. Follow the docstring convention from PATTERNS.md (render_cv.py lines 1-16).

    **Imports** (per RESEARCH.md lines 671-685):
    - `argparse`, `json`, `logging`, `os`, `sys`, `time`, `csv`, `traceback`
    - `from urllib.parse import urljoin`
    - `import requests`

    **Logging setup** (per PATTERNS.md jobspy_service.py pattern):
    - `logging.basicConfig(level=logging.INFO, format='%(asctime)s [%(levelname)s] %(message)s')`
    - `logger = logging.getLogger(__name__)`

    **Field type mapping dict** (per D-07, per RESEARCH.md lines 516-540):
    - `FIELD_TYPE_MAP` dict mapping Airtable type strings to NocoDB v3 type dicts
    - Keys: text, longText, singleSelect, multipleSelect, url, number, checkbox, date, dateTime, attachment, lookup, email, phoneNumber, currency, percent, duration, rating, rollup, formula, count, autoNumber

    **Helper functions** (all with docstrings per project convention):

    1. `_api_request(method, url, headers=None, json_data=None, retries=3)`:
      - Wrapper around `requests.request()` with:
      - 100ms delay between calls (rate limiting safety brake)
      - Retry on 429/503/ConnectionError up to `retries` times with 5s interval
      - Log request method, URL, status code
      - Parse JSON response, raise RuntimeError with response text on non-2xx
      - Return parsed JSON dict

    2. `wait_for_nocodb(base_url, timeout=120)`:
      - Poll `GET {base_url}/api/v1/auth/user/signin` every 5s
      - Return True when server responds (any status)
      - Raise RuntimeError if timeout exceeded
      - Per RESEARCH.md lines 864-879

    3. `signup_or_signin(base_url, email, password)`:
      - Try `POST /api/v1/auth/user/signup` first
      - If 200, log "First-time setup: admin user created", return token
      - If user already exists (any non-200), fall through to `POST /api/v1/auth/user/signin`
      - Raise RuntimeError if signin fails
      - Per RESEARCH.md lines 943-966

    4. `get_or_create_workspace(base_url, token)`:
      - Try `POST /api/v3/meta/workspaces` with title "JobSignal"
      - On 403/404 fallback: `GET /api/v3/meta/workspaces`, return first workspace id
      - If list empty, try v1 base creation as last resort: `POST /api/v1/db/meta/projects/` then extract workspace_id
      - Return workspace_id string
      - Log which method succeeded
      - Per RESEARCH.md lines 280-306

    5. `create_base(base_url, token, workspace_id)`:
      - `POST /api/v3/meta/workspaces/{workspace_id}/bases`
      - Body: `{"title": "JobSignal Engine", "meta": {"icon_color": "#36BFFF"}}`
      - Return base_id from response
      - Per RESEARCH.md lines 308-321

    6. `create_api_token(base_url, token, base_id)`:
      - `POST /api/v2/meta/bases/{base_id}/api-tokens`
      - Body: `{"description": "JobSignal Engine Bootstrap Token"}`
      - On 403 fallback: use JWT token directly (log warning)
      - IMPORTANT: Log the token value to stdout immediately (only chance to capture it — per Pitfall 5)
      - Return token string
      - Per RESEARCH.md lines 324-336

    7. `load_schema(schema_path)`:
      - Load and parse JSON file
      - Validate structure: has `tables` array, each table has `title` + `fields`, each field has `title` + `type`
      - Per RESEARCH.md lines 845-852

    8. `get_tables(base_url, token, base_id)`:
      - `GET /api/v3/meta/bases/{base_id}/tables`
      - Return response dict (contains `list` key)
      - Per RESEARCH.md lines 413-423

    9. `table_exists(tables_list, title)`:
      - Check if any table in `tables_list['list']` matches `title`
      - Return table dict or None

    10. `create_table(base_url, token, base_id, table_def)`:
      - `POST /api/v3/meta/bases/{base_id}/tables`
      - Body constructed from `table_def` dict (title, description, fields array)
      - Map `required: true` to `notNull: true` in each field
      - Do NOT include `options.choices` for SingleSelect/MultiSelect if choices array is empty (avoids 400 errors)
      - Return response dict with `id`

    11. `delete_table(base_url, token, base_id, table_id)`:
      - `DELETE /api/v3/meta/bases/{base_id}/tables/{table_id}`
      - Handle 404 gracefully (already deleted — log and continue)
      - Per RESEARCH.md lines 427-432

    12. `create_table_idempotent(base_url, token, base_id, table_def, force=False)`:
      - List existing tables, check if `table_def["title"]` exists
      - If exists AND force: delete, wait 1s, create
      - If exists AND not force: log skip, return existing table id
      - If not exists: create
      - Return table_id string
      - Per RESEARCH.md lines 897-916

    13. `import_csv_data(base_url, token, base_id, table_id, csv_path)`:
      - Read CSV with csv.DictReader
      - Batch records into chunks of 10 (safety brake)
      - `POST /api/v3/data/bulk/{table_id}` with array of record dicts
      - Log row count, any field mapping warnings
      - Handle 400 errors: log problematic fields, continue with remaining batches
      - Per RESEARCH.md lines 854-859, 881-892

    **`main()` function** (per RESEARCH.md lines 748-838):

    Build argparse parser with:
    - `--nocodb-url` (default: http://localhost:8080)
    - `--email` (default from env NOCODB_ADMIN_EMAIL, fallback admin@jobsignal.local)
    - `--password` (from env NOCODB_ADMIN_PASSWORD, required unless --skip-setup)
    - `--table` (optional, restrict to one table)
    - `--force` (flag, destructive)
    - `--import-data CSV_DIR` (seed from CSV files)
    - `--skip-setup` (flag, skip workspace/base creation — use existing)
    - `--token-only` (flag, only print API token from env and exit)

    Validation:
    - `--password` required if not `--skip-setup`
    - If `--table` specified but table not in schema, error and exit

    Execution flow:
    1. If `--token-only`: read NOCDB_API_TOKEN from env, print and exit
    2. Wait for NocoDB readiness
    3. Sign up or sign in to get JWT
    4. If not `--skip-setup`: workspace → base → API token (print token + instructions)
    5. If `--skip-setup`: get base_id from env `NOCODB_BASE_ID` or list bases and pick first; get API token from env `NOCDB_API_TOKEN`
    6. Load schema from `scripts/nocodb-schema.json` (same directory as script)
    7. If `--table`: filter tables list to matching title
    8. For each table: `create_table_idempotent()` with force param
    9. If `--import-data`: for each table, look for `{TableTitle}-Grid view.csv` in CSV_DIR; call `import_csv_data()`
    10. Log "Bootstrap complete."

    **Entry point:**
    ```python
    if __name__ == '__main__':
        main()
    ```

    ### Security Requirements (T-01-01, T-01-03):
    - NO hardcoded passwords, tokens, or secrets anywhere in the file
    - API token output to stdout only — stored in docker-compose env vars by the user
    - Signup credentials received via CLI args or env vars, not as defaults in code
    - `--force` mode: print "DESTRUCTIVE ACTION: This will drop and recreate tables. Are you sure?" and if stdin is a TTY, prompt for confirmation; in non-interactive mode (CI/piped), proceed without prompt

    ### Error Handling (per RESEARCH.md lines 918-931):
    - Every API call wrapped in try/except
    - Non-recoverable failures: `logger.error()` then `sys.exit(1)`
    - Transient failures: retry loop in `_api_request`
    - 401 on API call (token expired): log error, suggest re-running
    - 404 on delete: log and continue (already deleted)
    - 400 on field creation: log full request/response for debugging

    ### Follow Project Conventions (PATTERNS.md):
    - Shebang: `#!/usr/bin/env python3` (line 1)
    - 4-space indentation (PEP 8)
    - `snake_case` function names (e.g., `wait_for_nocodb`, `signup_or_signin`)
    - `_` prefix for private helper functions (`_api_request`)
    - Docstrings on every function
    - Logging with `logger.info()` / `logger.error()` (timestamped format)
    - `sys.exit(1)` on error (consistent with render_cv.py)
    - Max line length ~100 characters

    ### Do NOT include:
    - Any fenced code blocks or full inline implementations in this action — the executor reads the referenced source files for patterns
    - Links type fields (no cross-table relationships in Phase 1 per RESEARCH.md line 587)
    - MinIO/S3 configuration (local Docker volume per constraint in PROJECT.md)
    - Hardcoded credentials in default values for email/password (env var fallback only)
