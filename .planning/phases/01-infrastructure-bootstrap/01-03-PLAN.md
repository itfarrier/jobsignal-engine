<task type="auto">
  <name>Task 1: Start NocoDB stack and run bootstrap verification sequence</name>
  <files></files>

  <read_first>
    - docker-compose.example.yml (verify the NocoDB services are present)
    - scripts/nocodb_bootstrap.py (verify the script exists and is runnable)
  </read_first>

  <action>
    Execute the following verification sequence:

    1. **Start services:**
      ```bash
      docker compose -f docker-compose.example.yml up -d nocodb-postgres nocodb
      ```
      Wait 15-20 seconds for containers to initialize.

    2. **Verify containers are running:**
      ```bash
      docker compose -f docker-compose.example.yml ps --format "table {{.Service}}\t{{.Status}}\t{{.Ports}}" | grep -E "nocodb|nocodb-postgres"
      ```
      Both should show "Up" status.

    3. **Verify NocoDB UI is accessible:**
      ```bash
      curl -s -o /dev/null -w "%{http_code}" http://localhost:8080
      ```
      Should return 200.

    4. **Run full bootstrap:**
      ```bash
      python3 scripts/nocodb_bootstrap.py --email admin@verify.local --password verify-test-123
      ```
      Expect: exit code 0, "Bootstrap complete." log, API token printed to stdout.

    5. **Verify tables via NocoDB API (idempotency check — re-run is safe):**
      ```bash
      python3 scripts/nocodb_bootstrap.py --email admin@verify.local --password verify-test-123
      ```
      Expect: "already exists. Skipping." messages for all 4 tables. Exit code 0.

    6. **Test --table flag (single table):**
      Delete Pipeline table (or run --force for just Pipeline)... Actually, run:
      ```bash
      python3 scripts/nocodb_bootstrap.py --table Pipeline --force --email admin@verify.local --password verify-test-123
      ```
      Expect: Pipeline table recreated, other 3 tables untouched.

    7. **Test --force flag (all tables):**
      ```bash
      python3 scripts/nocodb_bootstrap.py --force --email admin@verify.local --password verify-test-123
      ```
      Expect: All 4 tables deleted and recreated. "Bootstrap complete." Exit code 0.

    8. **Test --token-only flag:**
      ```bash
      NOCDB_API_TOKEN=test-test python3 scripts/nocodb_bootstrap.py --token-only
      ```
      Expect: prints "test-test". Exit code 0.

    If any step fails, log the error and stop — do not proceed to next step. Report which step failed.

    Note: The bootstrap admin user created during step 4 will persist in the NocoDB database volume. This is expected — subsequent runs sign in, not sign up.
  </action>

  <verify>
    <automated>
echo "=== STEP 1: Checking containers ==="
docker compose -f docker-compose.example.yml ps --format "{{.Service}} {{.Status}}" | grep -E "nocodb" | grep -q "Up" && echo "OK: Containers running" || echo "FAIL: Containers not running"

echo "=== STEP 2: Checking NocoDB UI ==="
HTTP_CODE=$(curl -s -o /dev/null -w "%{http_code}" http://localhost:8080 2>/dev/null || echo "000")
if [ "$HTTP_CODE" = "200" ]; then echo "OK: NocoDB UI accessible (HTTP $HTTP_CODE)"; else echo "FAIL: NocoDB UI returned HTTP $HTTP_CODE"; fi

echo "=== STEP 3: Testing bootstrap ==="

echo "Exit code: $?"</automated>
  </verify>

    2. Sign in with: admin@verify.local / verify-test-123
    3. In the NocoDB UI, you should see the "JobSignal Engine" base with 4 tables:
       - **Profile** — Click to open. Verify these key fields exist:
         - Full Name (SingleLineText)
         - Core Skills (MultiSelect — should let you pick from a list)
         - Seniority Level (SingleSelect — should show Mid, Senior, Staff, Lead, Head)
         - Target Geography (MultiSelect — should show Canada, USA, Remote Global, etc.)
         - CV Markdown (LongText — multi-line text area)
         - Notification Email (Email — with email validation)
       - **Tracked Companies** — Verify:
         - Company Name, Careers URL, API Endpoint fields exist
         - Scan Method (SingleSelect — Greenhouse API, Ashby, Lever)
         - Enabled (Checkbox)
       - **Pipeline** — Verify (the most complex table, 28 fields):
         - Job ID (SingleLineText)
         - Apply Link (URL field)
         - Source (SingleSelect — LinkedIn, Indeed, Greenhouse, Ashby, Lever, Glassdoor)
         - Status (SingleSelect — New, Evaluated, Applied, Interview, Offer, Rejected, Archived)
         - Fit Score (Decimal — should accept decimals like 7.5)
         - Fit Tier (SingleSelect — High, Medium, Low)
         - AI Evaluation Cost (Decimal — accepts 6 decimal places)
         - Tailored CV (Attachment field)
         - Interview Questions (LongText)
       - **Search Queries** — Verify:
         - Source Type (SingleSelect — JobSpy)
         - Hours Old, Results Wanted (Number fields)
         - Last Run (Date field)
         - Enabled (Checkbox)

    4. Verify field type behavior:
       - Create a test record in Profile: fill in a few fields, save
       - Edit the record: check that SingleSelect fields show dropdown, MultiSelect show tag picker
       - Verify you can delete the test record after checking
