    ```python
    def get_or_create_base(base_url, token, workspace_id):
        """Find existing 'JobSignal Engine' base in workspace, or create one.

        GET /api/v3/meta/workspaces/{workspace_id}/bases to list existing bases.
        If a base titled 'JobSignal Engine' exists, return its id.
        Otherwise, call create_base() to create a new one.

        Args:
            base_url: NocoDB base URL
            token: JWT or API token for authentication
            workspace_id: Target workspace ID

        Returns:
            base_id string
        """
        headers = {"xc-auth": token}
        list_url = urljoin(
            base_url.rstrip("/") + "/",
            f"api/v3/meta/workspaces/{workspace_id}/bases",
        )

        try:
            data = _api_request("GET", list_url, headers=headers)
            bases_list = data.get("list", [])
            for base in bases_list:
                if base.get("title") == "JobSignal Engine":
                    base_id = base.get("id")
                    logger.info(
                        f"Using existing base 'JobSignal Engine' (id: {base_id})"
                    )
                    return base_id
        except Exception as e:
            logger.warning(f"Could not list bases: {e} — will create new base")

        logger.info("No existing base 'JobSignal Engine' found — creating new base")
        return create_base(base_url, token, workspace_id)
    ```

    Key design decisions:
    - Uses `_api_request()` (the shared retry wrapper) for the GET — unlike the ad-hoc `requests.get` calls in `get_or_create_workspace()`. This is appropriate because the bases endpoint is more stable and the retry logic adds resilience.
    - Catches exceptions broadly during the list phase so a transient API error falls through to `create_base()` rather than crashing.
    - `create_base()` is kept unchanged as the pure-creation primitive — `get_or_create_base()` calls it as a fallback.
    - Log messages distinguish between "Using existing base" and "creating new base" for clear operational visibility.
