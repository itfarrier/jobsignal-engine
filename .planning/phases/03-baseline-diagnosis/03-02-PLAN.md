<objective>
Build a pure JavaScript function `parseRunData(runData)` that extracts per-node item counts from an n8n execution runData structure.

Purpose: The measurement workflow's Code node (Plan 03) needs reliable parsing logic that correctly:
- Counts feeds generated from `Build Feed List` output
- Sums raw RSS items across all loop iterations of `RSS Feed Read` (per RESEARCH Pitfall 3)
- Sums parsed items across all loop iterations of `Parse & Filter Jobs`
- Counts items after within-run dedup (`Aggregate All Jobs`, filtering `_empty`)
- Counts net-new items after Pipeline dedup (`Deduplicate vs Pipeline`, filtering `_empty`)
- Counts Pipeline records created (`Create Pipeline Records`)
- Detects error conditions and safety brake triggers

TDD approach: Write tests with mock runData fixtures first, then implement the parser, then refactor. This ensures the parser is independently verifiable before being embedded in the n8n Code node.

Output:
1. `scripts/__fixtures__/mock-runData.mjs` — Mock execution data fixture
2. `scripts/parse-runData.mjs` — Parser implementation with default export
3. `scripts/parse-runData.test.mjs` — Test suite (Node.js with built-in test runner)
</objective>

  <behavior>
    The function `parseRunData(runData)` accepts an n8n execution `runData` object (maps node names to arrays of execution result entries) and returns a `MetricsResult` object:

    ```typescript
    interface MetricsResult {
      valid: boolean;
      error: string | null;
      feedsGenerated: number;
      totalRssItems: number;
      perFeedItems: Array<{ feedIndex: number; items: number; total: number }>;
      afterGeoFilter: number;
      perFeedAfterGeo: Array<{ feedIndex: number; items: number }>;
      afterDedup: number;
      netNewPipelineRecords: number;
      pipelineRecordsCreated: number;
      executionStatus: string;
      errorDetails: object | null;
      runDurationSeconds: number;
      startedAt: string | null;
      stoppedAt: string | null;
    }
    ```

    Key behaviors:
    - `feedsGenerated`: output length of `runData['Build Feed List'][0].output[0]`
    - `totalRssItems`: sum of `output[0].length` across ALL entries in `runData['RSS Feed Read']`, with `_empty` sentinels FILTERED OUT
    - `afterGeoFilter`: sum of `output[0].length` across ALL entries in `runData['Parse & Filter Jobs']`, filtering `_empty`
    - `afterDedup`: count from `runData['Aggregate All Jobs'][0].output[0]`, filtering `_empty`
    - `netNewPipelineRecords`: count from `runData['Deduplicate vs Pipeline'][0].output[0]`, filtering `_empty`
    - `pipelineRecordsCreated`: count from `runData['Create Pipeline Records'][0].output[0]`
    - `perFeedItems`: array with items per feed loop iteration (total and non-_empty counts)
    - `perFeedAfterGeo`: array with items after geo filter per feed loop iteration
    - `valid`: false if any required node is missing OR if feedsGenerated === 0
    - `error`: set if `latestExecution.data.resultData.error` or `latestExecution.error` exist
    - Null-safe accessors (?. pattern) on all paths to prevent crashes on unexpected structure
  </behavior>
  <implementation>
    Create three files:

    1. **`scripts/__fixtures__/mock-runData.mjs`** — Export a `buildMockRunData(options)` function that generates realistic runData matching the 01e node structure. Default: 5 feeds, ~30 total RSS items reducing through each stage. Also export `emptyRunData` for error-edge cases and `errorExecutionData` for safety-brake scenarios.

    2. **`scripts/parse-runData.mjs`** — Export default function `parseRunData(runData)`.
       - Accept a JIT-supplied execution data object wrapper `{ data: { runData }, status, startedAt, stoppedAt, error, ... }`
       - Use null-safe access throughout
       - Sum loop iteration outputs (not just count entries)
       - Filter `_empty` sentinels from real job counts
       - Detect and report error conditions
       - Return structured MetricsResult

    3. **`scripts/parse-runData.test.mjs`** — Test suite using Node.js built-in `node:test` + `node:assert`:
       - Test 1 (Normal execution 5 feeds): feedsGenerated === 5, totalRssItems === 30, afterGeoFilter === 22, afterDedup === 18, netNewPipelineRecords === 4, pipelineRecordsCreated === 4, valid === true
       - Test 2 (Empty/no feeds): feedsGenerated === 0, valid === false
       - Test 3 (All jobs already in Pipeline, _empty sentinel): netNewPipelineRecords === 0, pipelineRecordsCreated === undefined/0
       - Test 4 (Error execution with error data): valid === false or errorDetails populated
       - Test 5 (Missing node in runData): graceful handling, returns 0 for that metric, valid === false
  </implementation>
</feature>
