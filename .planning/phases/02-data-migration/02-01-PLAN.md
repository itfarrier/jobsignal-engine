<objective>
Migrate all existing Airtable data (4 tables — Profile, Tracked Companies, Pipeline, Search Queries) into NocoDB using NocoDB's native "Import from Airtable" feature.

Purpose: Move the pipeline's data into the self-hosted NocoDB database so that Phases 3-7 can replace Airtable nodes in workflows one at a time. Data sits ready in NocoDB while workflows continue running on Airtable during intermediate phases. Per D-06, all cross-table references are text/select field values — no formal linked record fields to map, so the native import carries these over as-is. Per D-07, new NocoDB record IDs are irrelevant because workflows query by field values (Status, Fit Tier, etc.).

Output:
- Modified `scripts/nocodb_bootstrap.py` with `--workspace-only` flag
- Airtable PAT and Shared Base URL created by user
- Empty "JobSignal Engine" workspace+base ready in NocoDB
- All 4 tables populated with complete data and attachments via native import
- Verifiable record counts and spot-check results confirming data integrity
</objective>

## Trust Boundaries

| Boundary | Description |

| NocoDB server ↔ Airtable API | Import runs over internet from NocoDB to Airtable's API |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-02-03 | Information Disclosure | Bootstrap terminal output | mitigate | API token printed to stdout once. Document: copy immediately, close terminal. |
| T-02-04 | Tampering | NocoDB → Airtable API (import) | mitigate | HTTPS transport for all Airtable API calls. NocoDB server initiates — no user-side injection point. |
